# 面向论文的研究方向与最小验证方案

[文档首页](README.md) · [会话交接](HANDOFF.md)

日期：2026-11-09。状态：选题建议，尚未实现新算法或运行论文实验。本轮对项目记录、作者论文/项目页和部分公开推理代码进行了针对性核查；这不是穷尽式查新，也不能保证录用或首次提出。

## 1. 已确认的目标与基础

用户明确希望研究**细粒度车型识别**，已有大约几万张图片、几千个车系的数据集。这是用户提供的规模信息，本轮没有访问该数据集；路径、标签层级、类别分布、近重复、真实天气覆盖及既有划分均待核查。不能把“车系标签”自动当成年款/配置标签，也不能凭平均样本数断言数据一定长尾。

项目已有可复用基础：

- NumPy/Pillow 物理天气基线、车辆轮廓及四部件区域配置。
- Qwen-Image-2.1 本地推理、原图保护、参数/种子/权重记录、批处理及部件裁剪预览。
- 四张原图的 16 个天气编辑结果。目视记录显示天气变化有效，但灯内细节、轮毂中心标识、小字等出现重绘；雪景还出现过额外路面标线。
- 尚无分类训练结果，不能把这些视觉问题直接等同于车系标签已经改变或识别性能必然下降。“保持原图不变”的同配置编辑诊断也尚未执行。

当前成果主要是实验基础和失败案例，尚不足以支持独立的方法创新。调整提示词、增加天气种类、接入现成 ControlNet、保留运行清单，都不能单独支撑较强的方法贡献。

## 3. 推荐主线：判别部件保真的天气增强

暂定题目：**面向细粒度车型识别的判别部件保真天气增强**。

核心问题：在天气确实改变的前提下，怎样保留区分易混淆车系所需的局部结构，并避免把合理的遮挡当成结构错误？

例如，两类车的差异可能集中在灯带形状与格栅分区。雨雾造成对比度下降不一定改变车系，而生成模型替换灯带设计可能破坏标签语义。车牌文字是否完全复现不是这个分类任务的核心指标；轮毂、饰件是否应强约束，也应由实际标签定义和类内变化决定。

待验证假设：相对于全局结构控制，**由车系判别性与天气可见性共同决定的部件约束**，能够在相当的天气强度下减少关键结构改写，并提高独立真实天气集上的分类表现。

候选贡献应落到一个机制及其证据，而非把多个现成模块罗列为创新：

1. **确定需要保护的判别结构。** 仅用训练/开发数据建立混淆关系；以车灯、格栅、车身轮廓等部件为单位，分析它们区分相邻车系的贡献。分类器响应需要结合部件定位与人工抽查，防止把车牌、店铺水印或背景当成判别部件。全图 Canny 同时包含结构、反射与阴影，不能直接视为纯几何真值。
2. **用可见性校准结构约束。** 将可见但被改写、合理天气遮挡、分辨率不足而无法判断分别记录。只在可判断区域计算结构保持证据，同时报告可判断覆盖率，避免通过遮住错误获得高分。已有物理雾/雨模块可产生结构不变的校准样本和模拟透射率；这些量是代理信号，不能当作生成图的真实可见性或真实气象标定。真实编辑的初期可见性由盲评标注，后续自动估计器需单独验证。
3. **把校准后的信息用于生成过程。** 在匹配 Qwen-Image-2.1 的控制分支上研究部件及时间相关的残差门控，保护可靠的判别结构，允许天气相关的照明、反射变化。先验证简单固定部件控制，再研究小型预测器；必须证明天气可见性与判别性提供了超出通用局部门控的增益。

这里的潜在区别是任务驱动的约束定义、可见性校准与真实识别收益。空间门控、部件掩码、对比学习各自都有前人工作，不能分别包装为首次提出。若最后只剩手调几个权重或筛掉困难样本，方法贡献仍然偏弱。

## 4. 技术落点与难度控制

已发现专门适配 2.1 的 [Qwen-Image-2.1-Fun-Controlnet-Union](https://huggingface.co/alibaba-pai/Qwen-Image-2.1-Fun-Controlnet-Union)。它是在 Qwen 2.1 底模上加载的控制分支，不需要为了结构控制必然换成 SDXL。权重尚未下载，本地尚未接入。

发布方 [VideoX-Fun 示例](https://github.com/aigc-apps/VideoX-Fun/blob/main/examples/qwenimage21_fun/predict_t2i_control.py) 使用 `QwenImage21ControlPipeline`。[控制模型源码](https://github.com/aigc-apps/VideoX-Fun/blob/main/videox_fun/models/qwenimage21_transformer2d_control.py) 暴露控制残差和全局 `control_context_scale`，提供了修改控制作用方式的入口；部件门控仍是需要开发、验证的新逻辑，不能把当前接口当成已经支持研究方案。还需验证原图参考条件、图像 token 对齐、KV cache 和条件分支共同使用的正确性。

第一版不训练整个 Qwen。可以先冻结底模与控制权重，通过小规模参数搜索建立“局部控制是否有效”的证据；若有效，再用开发集中的候选对及人工质量标注监督轻量控制器，减少逐图搜索开销。这一路径不要求立刻具备大规模同场景晴雨配对数据，但开发标注、控制器泛化和额外计算成本都需要真实测量。

先做阴天湿地和薄雾，隔离重光照/反射与空气散射问题；中雨随后验证。降雪与积雪会改变可见表面并遮住结构，作为后续扩展，不在第一轮同时解决全部天气机制。

当前纯 Qwen 2K 生成单张约 116.6 秒，峰值已分配显存约 65.5 GiB、保留约 76.4 GiB。增加控制分支后的耗时与显存未知，不能保证原配置仍可在单张 80 GB 卡上运行。先小规模测量，必要时统一降低所有对照分辨率或采用卸载。以现有纯 Qwen 速度线性估算，1,000 张仅生成就约 32.4 GPU 小时，不能一开始全量扩增几万张。

## 5. 实验必须回答什么

### 5.1 数据和划分

- 先核查标签含义、各类数量、近重复、来源/拍摄组、视角及天气覆盖。保留原始划分；若划分存在泄漏，另建明确命名的研究划分。
- 同一原图及其所有增强图必须跟随原图所属划分；同一车辆、拍摄组或商品图组尽量隔离。类别仍需满足所定义的闭集分类协议。
- 用户尚未确认真实恶劣天气图片数量。这是重要缺口：需要与训练标签可对应、独立留出的真实天气测试样本。普通车辆检测数据集的“car”标签不能直接替代细粒度车系标签。
- 没有真实天气测试时，只能先报告合成域实验，不能写成已经证明真实天气鲁棒性。可增加其他生成器/物理方法的测试作辅助，但不能用同一生成器的测试结果替代真实泛化。
- 生成控制器训练和调参只用训练/开发集；论文最终测试集在方法冻结前不参与选图、阈值选择、混淆对选择或早停。

### 5.2 对照和消融

| 对照 | 要排除的解释 |
| --- | --- |
| 原始训练 + 常规增强 | 基础分类能力与训练波动 |
| 物理天气增强 | 收益是否只是多了一些天气变化 |
| 当前 Qwen 直接编辑 | 部件控制是否有实际增益 |
| Qwen + 普通全局 ControlNet | 是否只需要现成结构控制 |
| Qwen + 固定部件控制 | 判别性/可见性机制是否优于简单掩码 |
| 完整候选方法 | 在相当生成预算和天气覆盖下验证整体效果 |

还需加入至少一个最接近的细粒度增强方法，例如 SaSPA；若主张相较现有天气编辑更好，再加入可复现的天气专用方法。不同底模的结果用于外部比较，机制因果优先依靠同一 Qwen 底模的消融。

消融至少去掉判别部件信息、去掉可见性校准、用静态门控替代动态门控。与通用局部控制思想做对照，区分任务监督和普通空间权重本身的收益。按实现情况增加“不做筛选/仅做筛选”，防止把选择效应归因于生成机制。

控制每类增强数量、天气/强度配额、分类器训练更新次数、源图、分辨率和生成预算；同配置可配对随机种子。若各方法接受率不同，分别报告等生成预算和等训练样本量结果，以及拒绝率与额外成本。

### 5.3 指标与可信证据

- **主指标：** 真实天气测试的宏平均车系准确率，兼报总体 Top-1、分天气结果、晴天性能与预先选定的易混类别错误。按实际类别分布决定是否报告头/中/尾类别。
- **机制证据：** 盲评的可见部件结构改写率、不可判断比例、天气目标达成率；分天气强度比较，不能因天气变弱而获得较高保真。人工评审至少两人复核一部分样本并记录分歧。
- **辅助指标：** 对齐后的局部边缘/特征相似度；相似度需先验证与人工结构判断的关系。不能只靠 CLIP、SSIM 或生成用教师的置信度认定标签保持。
- **可复现性：** 至少两个不同分类骨干、至少三个训练种子；报告均值、波动及按原始拍摄组/类别适当分组的置信区间。生成使用的评价器与最终评估模型尽量独立。
- 车牌和水印的遮蔽/裁剪审计应检查分类器是否依赖捷径；不以还原车牌文字作为车型识别贡献。

潜在论文论证链是：存在可重复的判别结构漂移 → 机制降低该漂移且没有削弱天气 → 在独立真实天气上带来分类收益。只改善视觉样图，不能直接完成最后一步。

## 6. 按步骤开展的最小验证

1. **数据审计与研究协议。** 获取数据位置/标签说明后做只读统计，确认真实天气测试是否可建。先选样本足够、外观相近的约 30–50 个车系作为开发范围；具体规模按数据分布调整，不假设每类都有足够照片。
2. **确认失败来源。** 对少量开发图比较缩放后的原图、VAE 编解码、保持不变的编辑及天气编辑。VAE 与不变编辑分开记录；这些是诊断，不把它们解释为天气失败的唯一原因。
3. **低成本概念验证。** 先用约 12 张开发原图做两种天气、一个种子、三种生成设置（直接 Qwen、普通 ControlNet、固定部件控制），约 72 张新候选；补充物理校准图和诊断图另计。这个规模只验证实现和问题是否值得扩大，不能做统计或论文结论。
4. **机制与训练小试。** 如果第 3 步存在改进空间，再扩到约 40 张开发图、两种天气、两个种子，加入可见性/判别性机制。逐步增加训练增强池，和相同训练预算的基线比较。四张现有展示图不作为独立测试集。
5. **扩大正式实验。** 只有在部件保真与识别效果均出现稳定信号后，才扩展更多车系、真实天气测试、完整消融及中雨/雪景。

停止或转向条件：

- 若普通 ControlNet 已在相当天气强度下解决主要漂移，新模块没有稳定增益，则不继续堆模块。
- 若部件相似度提升但独立分类性能不变，重新检查被保护部件是否与车系标签相关，而不是继续优化车牌/装饰小字。
- 若改善来自减弱天气、增加筛选次数或偏爱高置信易样本，不能据此声称新机制有效。
- 若没有可建立的真实天气测试，缩小结论范围并优先解决评价数据，不启动全量生成。

## 7. 论文定位和备选

这是一条可验证的选题候选，不是已被确认的新算法。现有项目适合支撑原型与对照，用户数据提供了做细粒度分类验证的基础；标签质量、真实天气测试与控制机制增益决定后续可行性。

如果方法增益不足，可以考虑以系统实证研究为主线：比较天气生成的视觉逼真度、细粒度标签可靠性和真实分类收益之间的关系。但该路线同样需要充分规模、明确新发现和严谨基准，不能把 16 张展示图包装成评测论文。暂不承诺某个会议、期刊或分区；完成最小验证后再按实际贡献选投稿目标。

本轮只完成选题调研和方案记录，未下载 ControlNet 权重、改变环境、训练分类器或启动生成任务。
